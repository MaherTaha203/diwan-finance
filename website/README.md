# الموقع الرسمي لديوان آل طه

موقع تعريفي عربي (RTL) من صفحة واحدة، بثلاثة أقسام فقط: **نبذة · التاريخ · الموقع**.
محوره البصري مجسّم ثلاثي الأبعاد لديوان آل طه، **محوَّل من التصميم المعماري المعتمد في Figma** دون إعادة تصميمه،
يقف داخل مشهد الصفحة نفسه (سماء التصميم وتلاله وساحة حجرية) بلا منصة عرض أو إطار،
ويدور حول محوره الرأسي تبعاً للتمرير فقط: الواجهة الأمامية ثم الجانبية ثم الخلفية.

> المجسّم تصوّر معماري للتصميم المعتمد، وليس تمثيلاً دقيقاً للمبنى الحقيقي.

هذا المجلد مشروع مستقل عن تطبيق المالية الموجود في جذر المستودع، ولا يشاركه أي ملف أو إعداد.

## التشغيل

يتطلب Node.js 20.19 أو أحدث (أو 22.12+).

```bash
cd website
npm install
npm run dev          # خادم تطوير على http://127.0.0.1:5173
npm run build        # بناء الإنتاج في dist/
npm run preview      # معاينة البناء على http://127.0.0.1:4173
npm run lint         # ESLint
npm run test:e2e     # اختبارات Playwright (تبني المشروع أولاً بـ npm run build)
npm run render:fallback  # إعادة توليد الصور الثابتة من النموذج الحقيقي
python3 tools/figma/extract_textures.py  # إعادة استخراج الخامات من تصميم Figma
```

تحتاج `test:e2e` و`render:fallback` إلى Playwright مع Chromium متاحين لـ Node (التثبيت العام يكفي).
تحتاج أداة الاستخراج إلى Python 3 مع `numpy` و`Pillow` و`opencv-python-headless`؛ مخرجاتها محفوظة في المستودع، فلا تلزم للبناء.

## تحويل تصميم Figma إلى مجسّم

التصميم المعتمد في ملف Figma «Diwan Al-Taha — Public Portal & Staff Gateway (Concept)» هو أربع لقطات واقعية
(الإطارات 1:2 نهاري، 1:3 للجوال، 1:4 ليلي، 1:5 تفصيل الوردة الحجرية). وهي **صور نقطية مسطّحة من زاوية واحدة**:
لا تحوي طبقات ثلاثية الأبعاد ولا متجهات ولا واجهات جانبية أو خلفية، فلا يمكن تدويرها مباشرة.
لذلك حُوِّلت تقنياً بدل إعادة رسمها:

| ما في التصميم | كيف نُقل إلى المجسّم |
|---|---|
| الباب الخشبي المقوّس بمساميره وحلقته | بكسلات اللقطة نفسها (`door.jpg`) على ورقة الباب |
| إطار القوس الحجري والكتفان والوسادتان | إسقاط مستوٍ لبكسلات اللقطة حول الباب (`arch.jpg`) |
| لوحة الوردة الثمانية | بكسلات لقطة التفصيل (`rosette.jpg`) مع نتوء من إضاءتها |
| الحجر المدقوق للجدران والقبة والساحة | وجوه الحجر الحقيقية من لقطة التفصيل، مرصوفة بمقاسات المداميك المقيسة على اللقطات |
| الزيتونة العتيقة | لحاء الجذع وأوراق التاج مقطوعة من الزيتونة في اللقطة النهارية |
| السماء والتلال والقرية | تدرّج سماء اللقطة وغيومها وتلالها في الخلفية |
| ألوان الأعمدة الزرقاء والخشب والقرميد | ألوان مُعايَرة من اللقطات (`src/scene/figma-palette.json`) |
| الأبعاد والنِّسب | مقيسة على اللقطات: الباب 1.30 م = 165 بكسل ⇐ 127 بكسل/م |

- أُزيلت الإضاءة الذهبية المحروقة في اللقطات من الخامات (de-lighting)، ثم تعيدها إضاءة الشمس في المشهد على كل الواجهات.
- الواجهتان الجانبيتان والخلفية غير ظاهرة في أي لقطة، فاكتُفي فيها بعناصر التصميم نفسه (الحجر والكرانيش والنافذة الزرقاء ذات المربعات) دون عناصر جديدة.
- مصادر التحويل محفوظة في `design/figma/`، وأداة التحويل `tools/figma/extract_textures.py` حتمية؛ إعادة تشغيلها تنتج الخامات نفسها في `src/assets/textures/`.

## سلوك النموذج ثلاثي الأبعاد

- الزاوية دالة صِرفة لموضع التمرير: لكل قسم زاوية مرساة (`FACADE_ANGLES` في `scroll-rotation.js`)،
  ويُستوفى بينها بمنحنى ناعم، مع تخميد أُسّي للحركة. التمرير للأعلى يعكس الدوران تماماً، ولا يوجد دوران تلقائي.
- الرسم عند الطلب فقط: لا تعمل حلقة `requestAnimationFrame` إلا أثناء الحركة أو بعد تغيير الحجم أو وصول خامة جديدة.
- يدور المبنى وشجرته وحدهما؛ السماء والتلال والساحة وجدار الشرفة ثابتة. لا قاعدة عرض: يرتكز المبنى على الساحة بظله وظل تماس خفيف.
- حواف المشهد تذوب في لون الصفحة (قناع CSS)، وتؤطّر الكاميرا المبنى داخل الجزء الواضح منها فلا يغيب في التلاشي.
- ثلاثة مستويات جودة (high/mid/low) تحدد دقة البكسل وحجم خريطة الظلال وكثافة أوراق الزيتونة ودقة الترشيح.
- تُحمَّل three.js في حزمة مستقلة بعد اكتمال تحميل الصفحة؛ تصل الخلفية وحجر الجدران والأوراق قبل أول إطار، وبقية الخامات تباعاً.
- عند غياب WebGL أو فقدان السياق أو تفعيل Save-Data أو `?static`: تُعرض صور ثابتة مُصيَّرة من النموذج نفسه وتتبدّل حسب القسم.
- مع `prefers-reduced-motion`: يثبت النموذج على الواجهة الأمامية دون دوران.

معاملات للتطوير والاختبار: `?static` (الوضع الثابت)، `?quality=high|mid|low`، `?capture` (يكشف واجهة تصوير للأداة).

بعد أي تعديل على المجسّم أو الخامات، شغّل `npm run render:fallback` لتحديث الصور البديلة.

## الموقع الجغرافي

الخريطة وزر الاتجاهات وزر الفتح في خرائط Google مبنية حالياً على اسم المكان فقط («سردا، فلسطين») دون إحداثيات،
لأن الموضع الدقيق للديوان لم يُعتمد بعد. يظهر ذلك للزائر صراحةً في قسم الموقع.

عند اعتماد الإحداثيات، عدّل الروابط الثلاثة في `index.html` (قسم `#location`):

| العنصر | القيمة الحالية | بعد اعتماد الإحداثيات (مثال: `LAT,LNG`) |
|---|---|---|
| إطار الخريطة | `maps.google.com/maps?q=سردا، فلسطين&z=14&output=embed` | `maps.google.com/maps?q=LAT,LNG&z=17&output=embed` |
| زر الاتجاهات | `google.com/maps/dir/?api=1&destination=سردا، فلسطين` | `google.com/maps/dir/?api=1&destination=LAT,LNG` |
| زر الفتح في الخرائط | `google.com/maps/search/?api=1&query=سردا، فلسطين` | `google.com/maps/search/?api=1&query=LAT,LNG` |

ثم احذف شارة «الموقع العام — الموضع الدقيق قيد التحديد» والملاحظة المرافقة لها.

## إضافة الصور والوثائق

الإطارات الفارغة في قسمَي التاريخ والموقع مخصصة لأصول حقيقية تُضاف لاحقاً:

- **أرشيف الديوان** (قسم التاريخ): ثلاثة إطارات `figure.frame--empty`: صورة تاريخية للديوان، وثيقة تاريخية، صورة قديمة للمدخل.
- **صورة الديوان أو مدخله** (قسم الموقع): إطار `figure.frame--wide`.

استبدل محتوى كل إطار بـ `<img>` يحمل `alt` وصفياً و`width`/`height` و`loading="lazy"`،
ثم أزِل الصنف `frame--empty`. يُفضّل WebP بعرض لا يتجاوز 1600px.

## النشر

يُنشر كمشروع Vercel مستقل، بجعل **Root Directory = `website`**، ولا يُغيَّر `vercel.json` في جذر المستودع.
يتضمن `website/vercel.json`:

- سياسة أمان محتوى صارمة، لا تسمح إلا بإطارات `www.google.com` و`maps.google.com`.
- `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy`، و`frame-ancestors 'none'`.
- تخزين مؤقت دائم (immutable) لملفات `/assets` ذات البصمة.
