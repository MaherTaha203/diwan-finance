# OUTPUT-002-C · UX Slice 3 — Canonical Arabic Ordering (Annual Debt)

**المطلوب:** أسماء تقرير المديونية السنوية مرتّبة **تصاعديًّا**، وبنفس الترتيب في **Screen = Print = PDF = Excel**. الفرز **قبل** التصيير، في المصدر المشترك. بلا مساس بـ FIN/القيم.

## السبب الجذري
`report-model.js::buildAnnualDebtModel` كان يأخذ صفوف المصدر 1:1 (بلا فرز) — فالترتيب يتبع مصدر البيانات، غير مرتّب بالاسم.

## الإصلاح (المصدر المشترك الصحيح)
الفرز يعيش **مرة واحدة** داخل `buildAnnualDebtModel` (قبل وضع الصفوف في `sections[].rows`). كل الأسطح تستهلك **نفس** `sections[].rows`، فترث ترتيبًا واحدًا — **لا فرز داخل أي renderer**.

- **Arabic-aware:** `Intl.Collator('ar', {numeric:true, sensitivity:'base'})` — يعالج ألف/همزة/آ (أ/إ/آ/ا تتوحّد)، والتشكيل، والأرقام المضمّنة.
- **حتمية:** عند تساوي الاسم، كسر التعادل برقم العضو (`code`).
- **fallback:** إن غاب `Intl` (بيئة قديمة) يبقى ترتيب المصدر.
- دالة مشتركة `sortByArabicName(list)` قابلة لإعادة الاستخدام لاحقًا (مثلًا للمتأخرين إن طُلب).
- **ترتيب عرض فقط — لا تغيير لأي قيمة/رقم مديونية.**

## التحقّق (حيّ + وحدة)
- **حيّ (Playwright، مصادَق):** استخراج ترتيب الأسماء من الأسطح الأربعة على نفس بيانات النظام:
  - MODEL / SCREEN / PRINT / PDF / EXCEL = `["أحمد آل طه","خالد آل طه","سعيد آل طه","محمد آل طه"]`
  - **All surfaces identical: true · ascending Arabic: true.**
- **اختبار وحدة** `tests/annual-debt-arabic-sort.test.cjs` (8/8) بأسماء عربية تكشف الفرز الساذج (ألف/همزة: آدم/أحمد/إبراهيم، «عبد الله»، أسماء مكرّرة، «محمد» آخِرًا) — يؤكّد التصاعد، وكسر التعادل بالرمز، وثبات القيم وعدد الصفوف.
- حزمة node: لا إخفاقات جديدة (حُدِّث اختبار موضعي واحد في `report-r7b-debt` ليؤكّد بالهوية لا بالموضع + يؤكّد الترتيب الجديد).

**النطاق:** تقرير المديونية السنوية (`ANNUAL_DEBT`) فقط، حسب الطلب. تقرير المتأخرين لم يُمَس (يمكن تعميم `sortByArabicName` عليه لاحقًا عند الطلب).
