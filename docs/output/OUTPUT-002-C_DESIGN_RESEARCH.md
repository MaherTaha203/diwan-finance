# OUTPUT-002-C — بحث تصميمي + نظام هوية الطباعة (Financial Enterprise)

**الهدف:** لا مستندات «جميلة» بل **احترافية** على طراز أنظمة المؤسسات (SAP / Oracle / Dynamics). الأولوية: الوضوح · القراءة · الاحترافية · المساحات البيضاء · الطباعة الممتازة — بلا تكرار أي معلومة، وبلا مساس بالمنطق المالي.

**المنهج:** مرحلة بحث قصيرة على مصادر مفتوحة المصدر منشورة (لم يُنسخ أي كود أو تصميم؛ استُخلصت الفلسفة والممارسات المشتركة فقط)، ثم اشتقاق نظام هوية طباعة خاص بديوان آل طه.

> نطاق التنفيذ (البند ٩): `Report Layout` · `Report Header` · `Report Footer` · `CSS` · `Output Components` فقط. **ممنوع** تعديل FIN / ReportModel / الحسابات / الأرقام.

### ٢) ما تعلّمناه من كل مصدر

- **sparksuite (1):** فلسفة «الطباعة = الشاشة» افتراضيًا، وحاوية واحدة `.invoice-box`، و`@media print` يزيل الظل/الحد/العرض الأقصى. الدرس: **بساطة الحاوية وتجريد زخرفة الشاشة عند الطباعة**.
- **anvil (2):** جداول دلالية (`table`) تُصيَّر جيدًا في HTML→PDF، وكتلة إجماليات محاذاة يمينًا. الدرس: **الجدول الدلالي هو العمود الفقري، لا صناديق**.
- **vinay (3):** انضباط «الصفحة الواحدة» وملاءمة الورق. الدرس: **الاقتصاد الرأسي**.
- **Inambe (4):** خطوط شعرية رفيعة (hairlines) بدل الحدود الثقيلة. الدرس: **الخطوط الرفيعة تكفي**.
- **nirajrajgor (5):** شبكة منظّمة. الدرس (وأيضًا رفض): الشبكة مفيدة لكن **وزن Bootstrap للطباعة زائد**.
- **crater (6):** الشعار مرة واحدة أعلى المستند، وقوالب متعدّدة بنفس البنية. الدرس: **شعار واحد أعلى، وبنية موحّدة**.
- **Invoice Ninja (7):** تقسيم المستند إلى **مناطق** (رأس/جسم/تذييل) مع كتلة هوية واحدة. الدرس: **تخطيط مناطقي واضح**.
- **Akaunting (8):** رأس تقرير **موحّد** عبر أنواع تقارير كثيرة. الدرس: **رأس/تذييل واحد مشترك لكل التقارير**.
- **Firefly III (9):** بيانات أولًا، لون مُقتصَد جدًا (دلالي فقط)، جداول هادئة. الدرس: **تقليل اللون؛ اللون يعني شيئًا (مدين/دائن) لا زينة**.
- **ERPNext Letterhead (10):** «ترويسة» تُعرّف مرة وتُعاد على كل مستند؛ ترقيم الصفحات من محرّك PDF لا من المحتوى. الدرس: **مصدر هوية واحد يُعاد استخدامه؛ الترقيم من المحرّك**.
- **Paged.js (11) + WeasyPrint (12):** الطريق القياسي إلى «صفحة X من Y» ورؤوس/تذييلات متكرّرة هو `@page` + `counter(page)/counter(pages)` — يعمل في محرّكات PDF الحقيقية، ويحتاج polyfill في المتصفّح. الدرس: **الترقيم الحقيقي عبر Paged Media، مع بديل متصفّح**.
- **Print-CSS best practices (13):** `thead`/`tfoot` بـ `table-header-group`/`table-row-group` لتكرار رؤوس الأعمدة، و`page-break-inside:avoid` للصفوف، وهوامش `@page`. الدرس: **رؤوس الأعمدة تتكرّر تلقائيًا — لا حاجة لشريط هوية متكرّر**.

### ٣) ما سنتبنّاه

1. **ترويسة واحدة مشتركة (Letterhead)** لكل التقارير الأربعة عشر والسندات الثلاثة — نفس البنية والمقاسات (من Akaunting / ERPNext / Invoice Ninja).
2. **الهوية تُعرض مرة واحدة فقط** أعلى الصفحة الأولى (شعار للطباعة/PDF فقط + اسم المؤسسة + اسم النظام + اسم التقرير + سطر سياق واحد).
3. **رؤوس الأعمدة تتكرّر** على صفحات الاستمرار عبر `table-header-group` — بدل شريط هوية متكرّر (يمنع التكرار).
4. **جداول دلالية بخطوط رفيعة**، أرقام tabular محاذاة يمينًا، بلا تظليل مزخرف (anvil / Inambe / Firefly).
5. **لون مُقتصَد**: حبر شبه أسود + خط رفيع + لون توكيد واحد + دلالة مدين/دائن فقط (Firefly).
6. **تذييل بسيط**: تاريخ الطباعة مرة واحدة + «صفحة X / Y» عبر `@page counter` (محرّكات PDF) واعتماد ترقيم المتصفّح في Chrome.
7. **الشاشة ليست الورقة**: لا شعار في العرض داخل النظام؛ الشعار للطباعة/PDF فقط (قائم منذ #252، نؤكّده).
8. **مساحات بيضاء وهوامش A4** مريحة، وانضباط رأسي.

### ٤) ما سنرفضه ولماذا

- **إطار Bootstrap للطباعة (5):** وزن CSS وأدوات زائدة لا تخدم ورقة مالية؛ نبقى على CSS خام موجَّه.
- **Paged.js كإلزام الآن (11):** إضافة اعتمادية ثقيلة تُعيد هندسة مسار `openPrintWin` وتُخاطر بمسار السند المعتمد (REPORT-001/QR). نؤجّله كتحسين اختياري لاحق، ونكتفي بـ `@page counter` القياسي + ترقيم المتصفّح.
- **الأنماط التزيينية (Magazine / Bauhaus / Luxury):** مرفوضة صراحةً — لا تخدم «احترافي لا جميل».
- **الصناديق الكبيرة المتكرّرة في الرأس:** مرفوضة (البند ٢) — تستهلك مساحة وتكرّر المعلومة.
- **تكرار الشعار/التاريخ/العنوان/الموقع** في أكثر من موضع: يُعتبر عيبًا تصميميًا (البند ١).

### ٥) كيف ينعكس ذلك على OUTPUT-002-C

يتحوّل محرّك التقارير (`report-layout.js`) وباني السندات (`print.js`) إلى **نظام هوية طباعة واحد**:
- رأس موحّد يُعرض مرة واحدة (البند ١ و٢)، سطر سياق واحد حسب نوع التقرير.
- إزالة **التثليث الحالي لتاريخ الطباعة** (كان في رأس + شريط تذييل + تذييل داخلي) → مصدر واحد.
- إزالة **شريط الهوية الجاري المتكرّر** (كان يكرّر العنوان/الموقع كل صفحة) → الاكتفاء بتكرار رؤوس الأعمدة.
- KPI مرة واحدة أعلى التقرير، بأسلوب Swiss مسطّح لا صناديق منتفخة (البند ٨).
- توقيع/QR لا يظهران افتراضيًا؛ يُفعَّلان من Output Profile (البند ٤).
- لوحة ألوان وطباعة Swiss/Enterprise موحّدة عبر كل النماذج (البند ٧ و١٠).

## الجزء الثاني — نظام هوية الطباعة (Diwan Print Design System)

### الرموز (Tokens)
- **الحبر:** أساسي `#1A2230` (شبه أسود)، ثانوي `#5A6472`، خافت `#9AA3B2`.
- **الخطوط الفاصلة:** رفيع `#E4E8EF`، أقوى `#C7CEDA`، حاجز `#1A2230` (للرأس والإجماليات).
- **التوكيد الوحيد:** `#2B3A5C` (كحلي مؤسسي) — يُستخدم بقلّة (خط الإجماليات/عناصر بنيوية).
- **الدلالة:** مدين `#B4552E` · دائن `#2F6B47` (فقط للحالة، لا للزينة).
- **الخطوط:** عربي `IBM Plex Sans Arabic` (النظام)، أرقام `IBM Plex Mono` (tabular، معزولة LTR).
- **المقاس:** A4، هامش `14mm`؛ عنوان `18px`، جسم `11px`، تذييل `8.5px`، سلّم مسافات 4/8/12/16.

### الرأس الموحّد (يُعرض مرة واحدة، صفحة ١)
```
[شعار — طباعة/PDF فقط]  اسم المؤسسة · اسم النظام            تاريخ الطباعة (مرة واحدة)؟→ ينتقل للتذييل
──────────────────────────────────────────────────────────  (خط حاجز)
                    اسم التقرير
سطر سياق واحد: العضو/الصندوق · الفترة · الفلاتر (حسب نوع التقرير)
```

### الجسم
- KPI (إن وُجدت): شريط مسطّح واحد أعلى التقرير — لا يُعاد داخل الجدول.
- جدول دلالي: رأس أعمدة يتكرّر (`table-header-group`)، خطوط رفيعة، أرقام يمينًا، صف إجماليات واحد في النهاية بخط حاجز.

### التذييل الموحّد (بسيط)
- يمين: «صفحة X / Y» (عبر `@page @bottom` counter؛ Chrome يعرض ترقيمه الخاص).
- يسار: «طُبع: التاريخ» **مرة واحدة** (المصدر الوحيد لتاريخ الطباعة — يُزال من الرأس).
- بلا اسم مؤسسة/موقع/وقت مكرّر.

### قواعد عدم التكرار (البند ١ + ١٠)
كل معلومة تعريفية **مرة واحدة**: الاسم/الشعار/العنوان/العضو/الصندوق/الفترة/الفلاتر/تاريخ الطباعة/الموقع/التوقيع/QR. أي ظهور ثانٍ = عيب.

### الشاشة مقابل الطباعة
- الشاشة: بلا شعار مستند، بلا رأس/تذييل جاري، بلا ترقيم صفحات.
- الطباعة/PDF: الشعار + الرأس الموحّد + التذييل + الترقيم.

### التوقيع/QR
- افتراضيًا **مخفيان** في التقارير. يظهران فقط عند تفعيلهما من Output Profile. السندات المعتمدة تحتفظ بمسارها (REPORT-001) دون مساس بالمنطق.
